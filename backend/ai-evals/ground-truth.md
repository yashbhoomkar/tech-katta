# Ground truth of the AI evaluator

`ground-truth.json` says, for each design a learner could submit to a Practice problem, what a correct AI review of
it must say. It is generated by `ground-truth.mjs` and checked by `test/ai-evals.test.js`, so it cannot drift from
the problems or the judge without a test failing.

## The cases

75 designs: for each of the 10 Practice problems (`content/problems2`), its reference solution (passes every test),
its wrong designs (55 in all, each written by the problem's author to fail in one known way) and its starting
template (cannot be judged until the learner finishes it).

## One case

```json
{
 "id": "url-shortener/no-cache-one-server",
 "kind": "wrong",
 "verdict": { "word": "Overloaded", "passed": 1, "total": 5, "first_failed": "t02-evening-peak" },
 "verdict_fails": true,
 "fault": "One small server can't take the evening peak.",
 "fault_parts": ["api"],
 "must_lead_with": ["finding:overloaded:GET_LINK:api", "finding:p99:GET_LINK:none"],
 "lead_says": ["api received 2,525 calls a second but can serve 500.", "…"],
 "never_a_problem": ["test:t01-quiet-afternoon"],
 "problems": ["verdict", "test:t02-evening-peak", "…"],
 "risks": ["load:api", "load:db", "static:W003:api"]
}
```

| Field | Meaning | Where it comes from |
|---|---|---|
| `fault` | The fault in the author's words | The problem file (`wrong[].why`); the author's expected verdict must equal the judge's, or the generator stops |
| `must_lead_with` | Fact ids a correct review cites in its first two items; any one is enough | The judge's findings in the first failed test (the cause, naming the part); else that test; else the errors that stop the design being judged. For a passing design: its tightest margin or a part already running hot |
| `fault_parts` | The parts at fault | The `must_lead_with` facts |
| `never_a_problem` | Facts the judge marked good: calling one a problem is wrong | The evidence pack |
| `problems`, `risks` | The judge's fail and risk facts | The evidence pack |

Fact ids are those of the evidence pack the model is sent (the production prompt, `src/ai/prompt.js`), so a model
can cite exactly these.

## When it changes

Changing a problem, the judge or the evidence makes `node --test` fail on the ground truth. Run
`node ai-evals/ground-truth.mjs`, read the diff of `ground-truth.json` (every changed `must_lead_with` should make
sense against the author's `fault`), and commit it with the change.

## Reviewing it by hand

Read `fault` against `lead_says` for each wrong design. They should name the same cause. If the judge's first
finding is not what a reviewer should lead with, correct the case in `OVERRIDES` in `ground-truth.mjs`, with a reason,
rather than editing the JSON. Read on 2026-11-16: all 55 agree on the cause. In a few the author's words name a
neighbouring part (image-serving/no-cdn says the load balancer, the judge measures the servers behind it): the
judge's fact stays the truth, because it is what the model is shown.
